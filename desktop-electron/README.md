# `<app>` — Electron desktop client template

> Companion repo: [beautifulelectron](https://github.com/Facta-Dev/beautifulelectron) — the
> Agent Skills and linter config for this stack.

A hexagonal, vertically-sliced **Electron 45 / TypeScript** desktop template:
one typed IPC contract enforced by a policy enforcement point, a thin main
process, a core worker that owns the SDK and storage, React 19 renderers with
plain-TypeScript view models, `node:sqlite` behind an async factory, and
Vite + Forge with a pinned fuse set. Every `<app>`, `<APP>` and `<scope>`
token is a **literal placeholder** until you rename. See
[How to apply](#how-to-apply).

## Layout

```
<app>/
├── src/
│   ├── main/            composition root: windows, app:// protocol, IPC PEP, core supervisor
│   ├── preload/         the sandboxed bridge: window.hmd.rpc + window.hmd.platform, nothing else
│   ├── core/            the app brain (utility process): rpc server + composition container
│   ├── renderer/        React entry, CorePort over the bridge, typing for window.hmd
│   ├── shared-kernel/   Result<T>, AppError taxonomy, ids, time (pure TypeScript)
│   ├── contracts/       wire + IPC contract: envelope, typed rpc map, zod schemas, policy
│   ├── platform/        the only OS-specific code: process.platform, paths, safeStorage
│   ├── infrastructure/  adapters: SDK client, storage (sqlite + in-memory), realtime (SSE), policy, logging
│   ├── features/        vertical slices, one per feature (never import each other)
│   │   └── notes/       example slice: domain · application · adapters · viewmodels · views
│   └── ui-kit/          reusable React components, theme, design tokens
├── packages/sdk/        generated client — regenerated, never hand-edited
├── tests/               vitest suites (contracts · main · features · infrastructure · shared-kernel) + _shared/fakes + _platform/architecture
├── tests/e2e/           separate Playwright-for-Electron package (not part of the default gate)
├── evals/               offline contract tests for the .claude layer (node --test) + live tier (run-live.sh)
├── docs/                15-chapter handbook + support matrix · admin guide · data flows · permissions register · 3 ADRs
├── .claude/             agents · skills · commands · schemas · settings · manifest · rules
├── scripts/             rename.sh · verify-template.sh · lint-*.sh · leak-guard.sh · instruction-budget.sh · install-claude-runtime.sh
├── PLAYBOOK_*.md        eight contracts (see Working with agents)
├── AGENTS.md            agent instructions; CLAUDE.md is a symlink to it
├── MEMORY.md            premise, process map, layer map, slices, stack, storage, gates
├── forge.config.ts      packaging + the fuse set (RunAsNode off, ASAR integrity on …)
├── vite.*.config.ts     four bundles: main, preload, core (all CJS .cjs) + renderer
├── tsconfig.*.json      five surfaces: main, core, preload, renderer, test
├── Makefile             ci · typecheck · lint · test · build · evals · package · fuses · e2e · verify
├── .env.example         placeholder values only — never real secrets
└── README.md            this file, post-rename
```

`pnpm-lock.yaml` is local only — it is gitignored and regenerated by the
first `pnpm install` on the renamed copy.

## Layer and process rules

One direction only, and machine-checked: **one `tsconfig` per target**
(`tsconfig.main/core/preload/renderer`, each with distinct `lib`/`types`),
`dependency-cruiser` graph rules, ESLint `no-restricted-imports`/`-globals`
walls, and `tests/_platform/architecture/architecture.test.ts` as test
evidence. Violations fail `lint` (depcruise side) or `typecheck`/`test`
(`tsc` side), not review.

| Concern | Lives in | May use | Must not use |
|---|---|---|---|
| composition root | `src/main/` | everything, `electron` | business logic, blocking calls |
| bridge | `src/preload/` | `contracts`, `platform` info | renderer code, core internals |
| app brain | `src/core/` | domain, application, adapters, SDK, `node:*` | `electron`, React, DOM |
| renderer | `src/renderer/`, slices' views/viewmodels | `ui-kit`, `CorePort`, contracts | `electron`, `node:*`, SDK, direct IPC |
| shared kernel | `src/shared-kernel/` | pure TS | contracts, platform, features |
| contracts | `src/contracts/` | zod, shared kernel | platform, infrastructure, features |
| slice domain | `src/features/<slice>/domain/` | shared kernel | `electron`, `node:*`, DOM, React, adapters |
| slice application | `src/features/<slice>/application/` | domain | Electron/Node/DOM APIs, adapters |
| slice adapters | `src/features/<slice>/adapters/` | application ports, platform, SDK | views, viewmodels |
| platform | `src/platform/` | Electron/Node APIs, `process.platform` | domain, application |
| sdk | `packages/sdk/` | TypeScript stdlib | `node:*`, `electron`, React |

Three processes ([docs/02](docs/02-processes-and-trust.md)): **main** (the
only process that touches Electron's privileged surface — keeps it thin), a
**core** `utilityProcess` that owns the SDK, session and storage, and
**untrusted renderers** behind `contextIsolation` + `sandbox`. Main is the
**enforcement point** for IPC; core executes the use cases.

## Prerequisites

- **Node 24+** (`engines.node >=24`) and **pnpm 11** (`packageManager: pnpm@11.10.0`).
- **Electron 45** (Chromium 156, Node 24; released 2026-10-20) — the binary is
  a dev dep; set `ELECTRON_SKIP_BINARY_DOWNLOAD=1` to install without it (the
  gates do not need the binary; e2e and packaging do).
- No display needed: unit tests run in the vitest **Node environment**; only
  `make e2e` wants a display and an Electron binary.

## The gate

```sh
make ci                  # typecheck (5 tsconfigs) + lint + test + build + evals
make test                # vitest run
make evals               # node --test evals/contracts.test.mjs (offline contracts)
make package             # electron-forge package; requires the Electron binary
make fuses APP=out/<name> # read the fuse table from the packaged app
make verify              # stages a renamed copy and re-runs every gate on it
make e2e                 # optional Playwright for Electron; SKIPs without a display/binary
```

The architecture law is executable: a forbidden import fails `lint`
(dependency-cruiser), a forbidden type surface fails `typecheck` (per-target
tsconfigs), and both re-fail in `tests/_platform/architecture/`.

## Working with agents

`AGENTS.md` (symlinked as `CLAUDE.md`) is the operating instruction file: hard
rules, the process model, the layer table, the IPC/security rules, gates, the
TDD loop, who edits what, and the playbook index. `MEMORY.md` holds the
premise — processes, layers, slices, stack, storage, gates, real gaps.

Seven contracts ship next to this file:

| File | Covers |
|---|---|
| `PLAYBOOK_DESKTOP_ELECTRON.md` | Platform model, three-process design, IPC, security, packaging, budgets |
| `PLAYBOOK_TESTS.md` | Test pyramid, environments, gates, SOC 2 / ISO 27001 evidence |
| `PLAYBOOK_SECURITY.md` | Threat model, secrets, TLS, supply chain |
| `PLAYBOOK_URLS.md` | Route naming, namespaces, error envelope |
| `PLAYBOOK_AUDIT.md` | Running an audit program (SOC 2 / ISO 27001 / ISO 9001) |
| `PLAYBOOK_CLAUDE_CODE.md` | The Claude Code kit, TDD loop, multi-session governance |
| `PLAYBOOK_FRONTEND.md` | UI copy, accessibility, shared design tokens |

(The stack playbook ships as its `_PART` pieces; the kit copy list is checked
by `check-playbook-copies.sh` in the parent `ai-coding-playbook` repo.)

The `.claude/` layer ships **11 agents** across four divisions (`core`,
`client`, `security`, `testing`), **21 skills** with 1:1 slash commands
(`/add-slice`, `/new-ipc-channel`, `/new-policy-key`,
`/electron-security-check`, `/electron-upgrade`, `/perf-regression`, plus the
adopted generic set `/plan`, `/spec`, `/review`, `/ship`, `/tdd`, `/learn`),
schema-driven linters in `scripts/`, a `PreToolUse` Bash guard and a
`manifest.json` target matrix for other runtimes.

```sh
bash scripts/lint-agents.sh
ALLOW_PLACEHOLDERS=1 bash scripts/lint-skills.sh     # pre-rename template
ALLOW_PLACEHOLDERS=1 bash scripts/lint-commands.sh
bash scripts/instruction-budget.sh
```

`ALLOW_PLACEHOLDERS=1` is the escape hatch for the **pre-rename** template,
where the placeholder tokens are intentional; after the rename the linters run
strict.

## How to apply

1. Copy this template to your repo root.
2. `bash scripts/rename.sh <app-slug> <scope>` — the
   `<scope> → <APP> → <app>` substitutions, in safe order, skipping
   `scripts/` and `evals/fixtures/`. Run **before** `pnpm install`.
3. `ELECTRON_SKIP_BINARY_DOWNLOAD=1 pnpm install`
   (drop the env var when you want the binary for e2e/packaging).
4. `pnpm format` — required once; the substituted token lengths re-align
   markdown tables.
5. `make ci` — green.
6. Replace the `notes` example slice with your domain.

## Installing the agent runtime

`scripts/install-claude-runtime.sh` copies `.claude/{agents,skills,commands}`
into the targets of `.claude/manifest.json` (Claude Code always-on; codex,
opencode, zed and other adapters) and writes `.claude/install-state.json`.

## ponytail notes

Deliberate simplifications are marked with a `ponytail:` comment naming the
ceiling and the upgrade path. The `notes` slice is a **worked example**, not
a feature to keep: delete it once your own slice exists.
